# Notion Dev Tracker

Notionの共通DBで、複数リポジトリの開発タスクをエージェントと管理するためのスキルです。案件ごとのタスク、依存関係、検証結果、次の操作を記録し、別のチャットから作業を再開できます。

現在は初版を開発中です。スキル、スキーマ、設定形式は変更されることがあります。

## スキル

| 名前 | 役割 |
| --- | --- |
| [notion-dev-tracker](skills/notion-dev-tracker/SKILL.md) | タスクの作成、着手、報告、レビュー、受け入れ、再開 |
| [notion-dev-tracker-setup](skills/notion-dev-tracker-setup/SKILL.md) | Notionの保存先確認、DBと案件の準備、プロジェクト設定、スキルと`AGENTS.md`の配置 |
| [notion-dev-tracker-migrate](skills/notion-dev-tracker-migrate/SKILL.md) | 既存のタスク管理を調査して移行案を提示し、ユーザーの同意後に移行 |

配布原本はこのリポジトリで管理します。案件とタスクの実データは、利用者が指定したNotionに保存します。

## 利用環境

初版の対応対象はCodexです。対象リポジトリを編集でき、利用者のNotion接続で次の操作ができる環境を想定しています。

- ページ、DB、データソースの取得
- DBの作成とスキーマの確認・更新
- リレーションの作成・確認
- タスクの検索、ページ送り、作成・更新

スキルは接続環境のツールを確認して使います。DBの保存先はセットアップ時に指定します。

## はじめ方

1. 対象リポジトリをCodexで開き、利用者のNotion接続を用意します。
2. [導入プロンプト](prompts/setup.md)のコードブロックをコピーしてエージェントに渡します。
3. 保存先を尋ねられたら、新しく作る親ページか既存DBのリンクを返します。
4. セットアップ結果の案件リンクとタスク件数を確認します。

エージェントは配布元を特定のコミットに固定し、3スキルの完全なディレクトリを同じ版で`.agents/skills/`へ配置します。`notion-dev-tracker-setup`と`notion-dev-tracker-migrate`は、同梱の`notion-dev-tracker`にあるスキーマと設定例を参照します。`references/`も含めて3ディレクトリをまとめて配置してください。

対象リポジトリには`.notion-dev-tracker.json`を作成し、接続先DBと案件の識別子を記録します。既存の`.project-tracker.json`がある場合は、セットアップで内容を確認して引き継ぎます。

## 既存のタスクを移行する

セットアップでタスク管理ファイルが見つかった場合は、移行スキルの実行を提案します。移行スキルは現在の管理方法とNotionのスキーマを調べ、対象範囲、項目の対応、既存データとの重複、正本の切替方法を提示します。ユーザーがその案に同意してから取り込みます。

## スキーマと案件ごとの運用

共通DBは案件を管理する`agent-epic`と、タスクを管理する`agent-backlog`の2つです。列名は小文字のスネークケースを使います。

- [DBスキーマ](skills/notion-dev-tracker/references/schema.md)
- [プロジェクト設定例](skills/notion-dev-tracker/references/project-config.example.json)

新規DBの状態名は英語を既定とします。既存DBの日本語などの状態名は、`status_values`の対応付けで利用します。必要な実行環境、統合先ブランチ、検証、受け入れの条件は対象リポジトリの指示に従います。

## 検証状況

現時点の検証範囲は、ファイル構成・参照・設定の静的チェックと、読み取り専用の模擬ケースです。実際のNotion DBでセットアップからタスク移行まで通す検証は、今後の確認対象です。
